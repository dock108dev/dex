[access documentation](https://tcgdex.dev/rest) specifies HTTPS GET and JSON;
`/v2/en/sets`, `/series/{id}`, `/sets/{id}` and `/cards/{id}` worked without an
API key in this bounded observation. No credential or portal configuration was
changed. One set-list request, one series-list request, 21 series detail requests,

Set IDs include punctuation such as `sv03.5`; card ID `sv03.5-123` is scoped by
language and variant in internal mappings. The card's `dexId: [123]` is canonical
mapping evidence, not a claim that every catalog record is resolved. Brief set
card lists lack the richer species/category/rarity/variant fields; all-era
normalization requires detailed records and explicit conflict review. Pocket,
promos and deck products must not be inferred to be physical booster pools.

The database's [MIT license](https://github.com/tcgdex/cards-database/blob/master/LICENSE)
is retained verbatim as `TCGDEX_LICENSE.txt` with its SHA-256. This supports the
metadata workflow; it does not establish rights to Pokémon artwork, rules text,
trademarks or third-party market data. The
[market integration documentation](https://tcgdex.dev/markets-prices) identifies
Cardmarket and TCGplayer pricing embedded in responses. Separate redistribution
permissions for those prices were not established, so artwork, rules text and
provider prices are excluded from public normalized packages. Raw card responses
stay private. No pricing integration or freshness promise was inferred from
advertised update frequencies. Two incorrect documentation-path requests returned
404 and are retained as source limitations; the available pricing document was
subsequently read using its documented link.

## E1 implementation and reproducible review

`beta/sealed_catalog.py` defines strict `dex-sealed-v1` models and separate public
entity tables for species, expansions, language/variant-specific printings,
booster membership, exact product versions, expansion-specific pack quantities,
guaranteed cards, seller-specific offers, immutable dated observations, sources
and coverage. References are validated transactionally through the service.
`sealed_imports` and `sealed_mappings` retain review/version journals and mappings.
The service reuses existing owner authorization, audit, hashing, transaction and
SQL helpers. Public records cannot contain private-copy fields. Member accounts
cannot review/import/report through this operator service; no new public HTTP
endpoint or private account projection was introduced.

The feature migration only adds tables. SQLite uses the application's IMMEDIATE
transactions; PostgreSQL writers use an explicit catalog lock. PostgreSQL runtime
migration was not exercised in this slice. The CLI applies the migration explicitly
against the selected prepared root; existing installations are not auto-migrated.

Preview → verify → publish is explicit. Identical package imports return the same
journal; reused source versions, changed immutable records, remapped external IDs,
wrong languages, dangling relationships, uncorroborated booster pulls and unsupported
contents/stock claims are rejected. New dated observations require new source and
observation identities; historical checks retain their times. Rollback requires
the unchanged current publication and archives newly introduced identities;
external mappings remain reserved. Roll back later publications first. Publishing
after rollback uses a fresh package version and preserves archived identity meaning.
A future corrective metadata/mapping review workflow and integration into the
existing browser catalog surface remain full-E1 follow-on work.

Offer states are in-stock, out-of-stock, preorder and unknown. Freshness is at most
24 hours from the original checked time; future-dated observations are not fresh.
Only the latest observation for an offer may qualify `buy_now`, and only with
fresh in-stock evidence, price and known seller identity. Report/import times
never replace checked time. Preorders remain separate. Unknown values remain null.
Guaranteed inclusions are separate from possible booster pulls. No pull odds,
cost allocation, expected completion cost or sealed valuation is calculated.
