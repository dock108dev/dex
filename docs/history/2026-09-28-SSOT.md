# Current source-of-truth map

September 28, 2026. Base commit `a18baf6` plus the uncommitted error-handling,
security and SSOT passes. This is a source refactor, not a data cutover or a
replacement for a retained staging build. [ROADMAP](2026-09-28-ROADMAP.md) controls current
scope; PM status and historical B0–B5 records do not override it.

## Domain ownership

Domain: routing and supported environments
SSOT module/file: `src/pokemon_hunter/beta/urls.py`, `beta/settings.py`
Why this is authoritative: Django selects routes from the initialized root's
capabilities and explicit local/staging profile. Each URL is registered once with
the selected handler; newer capabilities do not shadow older duplicate routes.
The legacy app has its own
`app.create_app` entry point and never supplies authenticated routes.
Known callers: `beta.cli serve`, `beta.deployment web`, Django request handling;
legacy `pokemon-hunter app` calls `app.serve`.

Domain: authentication and authorization
SSOT module/file: Django authentication plus `beta/accounts.py`, `beta/store.py`
Why this is authoritative: Django owns passwords, sessions and tokens;
`principal`/`verified` resolve active accounts and roles on the server.
Known callers: views, collection operations, scans, catalog services and workers.

Domain: authenticated inventory persistence and mutation
SSOT module/file: `beta/collection.py`, `beta/transactions.py`
Why this is authoritative: private physical copies and preview/confirm/undo
operations in the selected inventory database drive authenticated projections.
Known callers: collection views, scan confirmation, catalog resolution and parity.
Original-app ownership is separately written through `collection.update_card` to
its configured JSON. Neither store automatically overwrites or reconciles the
other. The roadmap requires preserving both until explicit reconciliation.

Domain: collection hunt request validation and result policy
SSOT module/file: `hunt.SearchRequest`, `hunt.project_results`
Why this is authoritative: both apps now use the same allowed fields, budget,
pool/focus filters, auction bid cap and result ordering. Unknown request fields
are rejected instead of silently ignored by the original app.
Known callers: original `app.create_app` search/reopen/reveal routes and
`beta.parity` sample/saved/reveal routes. Framework-specific HTTP statuses remain
422 for FastAPI schema rejection and 400 for Django validation rejection.

Domain: hunt evidence analysis and spoiler projection
SSOT module/file: `hunt.analyze`, `hunt.public_listing`, `hunt.query_plan`
Why this is authoritative: seller evidence, eligibility and hidden/revealed output
are shared. Authenticated parity adds account scoping, opaque result IDs and its
stricter spoiler projection; it does not duplicate ranking/filtering policy.
Known callers: both apps' hunt paths. The explicitly preserved legacy lot watcher
uses `normalize.evaluate` for a different bulk-alert contract, not collection hunts.

Domain: scan configuration validation and defaults
SSOT module/file: `beta/scan_config.py`
Why this is authoritative: one pure validator defines supported runtime providers,
boolean enablement, finite spending ceilings and local defaults. Storage adapters
read their inputs and delegate validation; persistent/copied inputs must be complete.
Known callers: `scans.config` for local JSON and persistent settings,
`deployment.migrate_copy` for sidecar validation, and `deployment.initialize`
for initial defaults. The copy importer separately retains its explicit prohibition
on `codex_cli`; that restriction is a staging import boundary, not an alternate
implementation of general configuration validation.

Domain: photo jobs and provider selection
SSOT module/file: `beta/scans.py`, `beta/scan_worker.py`
Why this is authoritative: durable scan jobs own attempts, reservations, matching,
confirmation and explicit provider choice. The worker runs this service, not a
second generic job store. `codex_recognition.py` is the CLI transport only.
Known callers: scan views, local worker thread, standalone worker and bounded
operator evaluator. Manual, fixture, openai and codex_cli remain supported.

Domain: catalog ingestion and publication
SSOT module/file: `beta/catalog_imports.py`, `beta/catalog_requests.py`
Why this is authoritative: owner-reviewed versioned packages and consent-scoped
requests control publication, rollback and same-copy resolution.
Known callers: catalog views and explicitly invoked preparation/import workflows.

Domain: valuations and price refresh
SSOT module/file: `valuation.valuation_records`, `scripts/refresh_values.py:main`
Why this is authoritative: guide matching/staleness lives in the shared valuation
function; the refresh command uses its current console-table parser. Its unused
alternate product-page parser and conflicting field mapping have been deleted.
Known callers: original app, authenticated parity, explicit operator refresh.
Hunt condition-qualified raw bid calculations remain a distinct evidence domain.

Domain: browser security and safe failures
SSOT module/file: `security.py`, `beta/diagnostics.py`
Why this is authoritative: shared browser headers and seller URL validation are
used by both apps; authenticated failure diagnostics omit private content.
Known callers: app/middleware responses, hunt/watcher links, authenticated request
and worker boundaries. See [security](../SECURITY.md) and [error handling](../ERROR_HANDLING.md).

## Tests and follow-up

The routing/configuration follow-up adds tests for one registration per URL across
B1, B2, parity, B4 and staging profiles, exact selected handlers, shared-policy
calls from both readers and copied import, finite/type validation, complete-input
requirements, and rejection before opening a copied database. Existing staged
files, owner roots and frozen builds remain untouched. The UI cleanup is preserved.


Route-level tests patch the shared hunt projection while exercising search,
reopen and reveal in each app, proving all three use it. Unknown-field requests
are rejected by both. Existing filter/budget, spoiler, ownership, authorization
and safe-link tests remain. The test-only B1 worker contract tests were replaced
with checks that unsupported resource kinds/routes remain unavailable; actual
scan-worker coverage remains in B3/CLI tests.

Future removal of B1 schemas/markers or the original app requires an explicit
inventory of prepared roots and a separate migration/retirement decision. No
owner-data inspection, migration or reconciliation is performed for this pass.
Do not delete historical evidence to make the source appear simpler. Staging
retirement or reactivation is also a scope decision, not inferred from inactivity.

Validation uses temporary synthetic state, the installed Python environment and
focused tests. No provider calls, server restart, packaging or release is involved.

## Repository maintenance boundaries

The root README is the current entry point; `docs/ORIGINAL_APP.md` owns preserved
original-app setup, data and pricing instructions. `APP_SPEC.md` is explicitly the
original-app specification, with historical results labeled accordingly.

`docs/ui-before/` has no runtime/test callers. Its three historical source snapshots
were removed from the Git index during cleanup, with local bytes preserved and
verified by SHA-256. They are ignored, local-only evidence; earlier commits still
contain them. Current `web/` assets, catalog inputs and synthetic fixtures remain
tracked. A fresh working-source export without snapshots/private state passed the
15 original-app tests. No history rewrite, commit or push was performed.

Cohesive transactional collection code and existing frontend modules remain in place;
this pass does not split them merely by line count. A frontend formatting/extraction
pass should be separate from behavioral work and verified against the retained UI
captures. Existing broad private-media exclusions remain for safety; adding authored
media later requires a reviewed path-specific exception, not exposing private images.
